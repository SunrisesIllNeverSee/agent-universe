Token leverage ≈ Useful result ÷ Tokens consumed

There are several ways token leverage can improve:

Context leverage: Give the model the few pieces of information that strongly affect its answer instead of dumping everything into the prompt.

Reasoning leverage: Spending somewhat more tokens on reasoning can sometimes prevent an expensive mistake or eliminate several additional model calls.

Reuse leverage: Prompt caching, reusable summaries, or persistent context can keep you from repeatedly sending the same large input.

Tool leverage: A relatively small model call might trigger a database query, calculation, search, or code execution that accomplishes much more work than generating the information token-by-token.

Output leverage: Asking for structured output that feeds directly into another workflow can make the same number of generated tokens substantially more valuable.

The ingest pipeline checks whether the four token pillars add up, whether sessions/turn counts make sense, output rate, cache-read/cache-write relationships, minimum input share, and cadence. For example, extremely low input combined with huge cache reads—an obvious way to exploit Υ=CR×O/I2—gets flagged. GitHub+1

Replay and rate controls. Duplicate snapshot hashes and repeated device/window submissions can be rejected, and there is a per-device submission cap; the database also has an atomic throttle to avoid racing the rate limit with concurrent requests. GitHub

Historical log attestation. SigRank can hash source files and remember their hashes, timestamps, and modification times. If a previously seen log suddenly changes without the session timestamps changing, or appears to have been edited after the session ended, that produces a tampering signal. GitHub

Anomaly detection. There is also a server-side verification battery aimed at suspicious digit distributions, unnatural cadence, and cache inflation/observer contamination. GitHub

The important limitation is that cryptographic signing proves “this enrolled device submitted these numbers,” not “these numbers represent genuine productive AI work.” Since SigRank deliberately does not upload prompts or responses, it cannot directly judge whether 100,000 output tokens were valuable code versus deliberately generated junk. Likewise, a determined attacker who controls their local machine could potentially fabricate plausible-looking session data rather than merely editing an existing log. Historical attestation raises the cost, but it is not equivalent to provider-signed telemetry or hardware remote attestation. This is an inference from the architecture described in the public code. GitHub+1

There’s also a Goodhart’s-law issue distinct from outright cheating: because Υ explicitly rewards high cache reuse and output relative to fresh input, someone can intentionally structure real usage to maximize the formula. The plausibility bounds stop the most absurd configurations, but they cannot prove that the resulting activity was useful. GitHub+1

One thing I noticed in the current code is worth highlighting: anomaly flags presently appear to be recorded for review but do not themselves block or downgrade a submission; only reject-severity findings block it. The source comments say this was changed to avoid false positives that had excluded legitimate users. GitHub So the strongest defenses today are signatures, enrollment, replay/dedup, hard plausibility rejects, throttling, and historical attestation—not the statistical anomaly detector alone.

So I’d summarize SigRank as tamper-resistant and fairly costly to game casually, rather than mathematically ungameable. The next major step toward stronger cheat resistance would be cryptographically verifiable telemetry directly from Anthropic/OpenAI/etc., because that would move the trust boundary away from a user-controlled local log.

The Conservation Law of Commitment is a recently proposed principle in Commitment Theory, developed by Deric J. McHenry in 2026. It concerns what happens to the binding meaning of language when that language is repeatedly transformed—for example, summarized, paraphrased, compressed, or passed through multiple AI agents. A message’s essential commitment can remain unchanged through transformations, but only if the transformation process actively enforces preservation of that commitment.

A common formulation is:

C(T(S))≈C(S)

where S is the original signal, T is a transformation, and C(S) represents its commitment content—the minimal meaning that must survive for the statement to retain its identity and force. Without enforcement, the theory predicts that repeated transformations cause commitment to degrade. Mos2es+1

The contrast is roughly:

Opinion / perception eval: “How helpful did you find the AI, 1–5?”

Performative / task eval: “Can the user successfully complete this workflow with the AI, and what errors occur?”

Benchmark eval: “What percentage of a fixed test set does the model answer correctly?”

For users specifically, performative evals are valuable because an AI can sound impressive while still making the user’s actual job harder. A realistic eval can measure things such as task completion, corrections required, time saved, whether important information was missed, and whether the user could safely rely on the outcome.
